## 核心发现总结

### 1. Neovim 双脚本系统架构

```
┌─────────────────────────────────────────────────────────────────┐
│                         Neovim 架构                              │
├─────────────────────────────────────────────────────────────────┤
│  用户脚本层                                                       │
│  ┌─────────────────┐     ┌─────────────────┐                   │
│  │   init.lua      │     │   init.vim      │                   │
│  │   (现代配置)     │     │   (传统配置)     │                   │
│  └─────────────────┘     └─────────────────┘                   │
│           │                      │                                │
│           ▼                      ▼                                │
│  ┌─────────────────┐     ┌─────────────────┐                   │
│  │  Lua Runtime    │     │ Vimscript Runtime│                   │
│  │  vim/lsp         │     │  syntax/*.vim   │                   │
│  │  vim/treesitter  │     │  indent/*.vim   │                   │
│  │  vim.diagnostic  │     │  ftplugin/*.vim │                   │
│  └─────────────────┘     └─────────────────┘                   │
│                          │                                      │
│                          ▼                                      │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │                    核心 C 层                              │   │
│  │  normal.c, ops.c, buffer.c, window.c, edit.c, search.c  │   │
│  │              完全独立于脚本系统                            │   │
│  └─────────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────────┘
```

### 2. 删除脚本系统的影响对比

```
┌─────────────────────────────────────────────────────────────────┐
│                    删除哪个脚本系统更致命？                        │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  删除 Vimscript:                                                 │
│  ├── 失去: 用户体验层 (syntax, indent, ftplugin)                │
│  ├── 可替代: 用 Lua/Tree-sitter 重写                             │
│  ├── 影响: 老插件不工作                                          │
│  └── 方向: Neovim 的演进方向                                      │
│                                                                  │
│  删除 Lua:                                                        │
│  ├── 失去: 核心差异化功能 (LSP, Tree-sitter, Diagnostic)         │
│  ├── 不可替代: 这些功能是 Lua 实现的                              │
│  ├── 影响: 现代插件生态全部丢失 (95%+)                            │
│  └── 结果: 回退到"传统 Vim + 异步"                               │
│                                                                  │
├─────────────────────────────────────────────────────────────────┤
│  结论: 删除 Lua 比 删除 Vimscript 影响更大                       │
│        因为现代 Neovim 的核心功能都是 Lua 实现的                  │
└─────────────────────────────────────────────────────────────────┘
```

| **现代插件** | ❌ | ✅ | ❌ |

## Chez Scheme 替代方案分析

### 方案对比

```
┌─────────────────────────────────────────────────────────────────┐
│                    三种方案对比                                  │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  方案 1: 保持现状 (Lua + Vimscript)                             │
│  ├── 技术可行性: ★★★★★                                        │
│  ├── 实际可行性: ★★★★★                                        │
│  └── 建议: ✅ 推荐                                               │
│                                                                  │
│  方案 2: 嵌入 Chez Scheme 到 Neovim                             │
│  ├── 技术可行性: ★★★★☆                                        │
│  ├── 实际可行性: ★★☆☆☆                                        │
│  ├── 主要障碍: 二进制大小、启动时间、事件循环集成、生态归零    │
│  └── 建议: ⚠️ 不推荐直接替代，可考虑作为第三语言               │
│                                                                  │
│  方案 3: 反向架构 - 将 Vim 嵌入 Chez Scheme                     │
│  ├── 技术可行性: ★★★★☆                                        │
│  ├── 实际可行性: ★★★★☆                                        │
│  ├── 主要优势: libvim 已存在，FFI 成熟，创建新产品              │
│  └── 建议: ✅ 可行，创建 Scheme-native 编辑器                   │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
```

### Chez Scheme 嵌入 Neovim 的主要障碍

| 挑战 | Lua | Chez Scheme |
|------|-----|-------------|
| **设计目标** | 嵌入语言 | 通用语言 + 编译器 |
| **二进制大小** | ~200 KB | 5-10 MB |
| **启动时间** | <5ms | 50-80ms |
| **事件循环集成** | 原生支持 | 需要复杂适配 |
| **生态影响** | 无 | 95%+ 插件丢失 |

## TUI 选项分析

如果采用反向架构 (Chez Scheme + libvim)，需要选择一个终端 UI 库：

### TUI 库对比

| TUI 库 | 推荐度 | 优势 | 劣势 |
|--------|--------|------|------|
| **libtickit** | ⭐⭐⭐⭐⭐ | 与 libvim 同生态、现代 API、24位颜色 | FFI 需 C 桥接 |
| ncurses | ⭐⭐⭐⭐ | 成熟稳定、广泛兼容、FFI 简单 | API 较旧 |
| notcurses | ⭐⭐ | 功能最丰富、图像支持 | 体积大 |
| 自定义 ANSI | ⭐⭐ | 零依赖、完全控制 | 开发量大 |

### FFI 绑定复杂度

| 维度 | libtickit | ncurses |
|------|-----------|---------|
| **FFI 复杂度** | 高 (需 C 桥接) | 中 (纯 Scheme) |
| **开发时间** | 4-8 周 | 1-2 周 |
| **回调处理** | 必须用 trampoline | 可选 |
| **参考实现** | 几乎没有 | Racket, Gambit 有 |

### 建议

- **快速开发**: ncurses (1-2 周)
- **与 libvim 配套**: ncurses 原型验证后评估

## 最终结论

```
┌─────────────────────────────────────────────────────────────────┐
│                        最终建议                                  │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  1. 对于 Neovim 本身:                                           │
│     ✅ 保持 Lua + Vimscript 双脚本系统                          │
│     ✅ 这是经过验证的架构                                        │
│     ✅ 拥有丰富的生态                                            │
│                                                                  │
│  2. 如果想要 Scheme 支持:                                        │
│     ✅ 作为第三语言渐进式添加                                    │
│     ⚠️ 不要直接替代 Lua 或 Vimscript                            │
│     ⚠️ 需要解决事件循环集成问题                                  │
│                                                                  │
│  3. 如果想要 Scheme-native 编辑器:                               │
│     ✅ 使用反向架构 (Vim 嵌入 Scheme)                           │
│     ✅ 基于 libvim 构建                                          │
│     ✅ 创建新产品，不是修改现有项目                              │
│                                                                  │
│  4. 关键洞察:                                                    │
│     • Neovim 的核心编辑功能是 C 实现，独立于脚本系统             │
│     • Lua 实现了核心差异化功能 (LSP, Tree-sitter, Diagnostic)   │
│     • 删除 Lua 比删除 Vimscript 影响更大                        │
│     • 反向架构比嵌入 Scheme 到 Neovim 更可行                    │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
```
