## 2. Chez Scheme 嵌入 API

### 2.1 初始化流程

```c
#include "scheme.h"

int main(int argc, char *argv[]) {
    // 1. 初始化静态内存
    Sscheme_init(NULL);
    
    // 2. 注册 boot 文件 (必需)
    Sregister_boot_file("/path/to/petite.boot");  // 核心运行时
    Sregister_boot_file("/path/to/scheme.boot");  // 编译器 (可选)
    
    // 3. 构建堆并加载 boot 文件
    Sbuild_heap(argv[0], NULL);
    
    // 4. 执行 Scheme 代码
    ptr result = Scall1(
        Stop_level_value(Sintern("my-function")),
        Sfixnum(42)
    );
    
    // 5. 清理
    Sscheme_deinit();
    
    return 0;
}
```

### 2.2 核心 API 函数

| 函数 | 用途 |
|------|------|
| `Sscheme_init()` | 初始化静态内存 |
| `Sregister_boot_file()` | 注册 boot 文件 |
| `Sbuild_heap()` | 构建堆，完成初始化 |
| `Sscheme_deinit()` | 关闭并清理 |
| `Scall0()`, `Scall1()`, ... | 从 C 调用 Scheme 函数 |
| `Stop_level_value()` | 获取顶层绑定 |
| `Sintern()` | 创建/获取符号 |
| `Sfixnum()` | 创建 fixnum |

### 2.3 Boot 文件

| 文件 | 大小 | 用途 |
|------|------|------|
| `petite.boot` | ~1-2 MB (压缩) | 核心运行时 (必需) |
| `scheme.boot` | ~2-4 MB (压缩) | 完整编译器 (可选) |
| `kernel.o` | ~2-3 MB | C 运行时 |
| **总计** | **~5-10 MB** | vs Lua ~200KB |

Boot 文件使用 LZ4 压缩 (默认)，启动时间：
- 完整 Scheme: ~80ms
- 仅 Petite: ~58ms

## 3. 回调机制 (C ↔ Scheme)

### 3.1 Scheme 调用 C (容易)

使用 `foreign-procedure` 直接声明 C 函数：

```scheme
;; 声明 C 函数
(define printf
  (foreign-procedure "printf" (string int) int))

;; 调用
(printf "Hello %d\n" 42)
```

### 3.2 C 调用 Scheme (复杂)

需要使用 `foreign-callable` 并锁定对象：

```scheme
;; 创建回调
(define make-callback
  (lambda (proc)
    (let ([code (foreign-callable 
                  proc 
                  (char)    ; 参数类型
                  void)])   ; 返回类型
      (lock-object code)  ; 关键！防止 GC 重定位
      (foreign-callable-entry-point code))))

;; 使用示例
(define my-callback
  (make-callback 
    (lambda (c) 
      (printf "Received: ~c\n" c))))

;; 传递给 C (作为整数地址)
```

### 3.3 关键限制

```
┌─────────────────────────────────────────────────────────────────┐
│  重要警告: 必须调用 lock-object                                 │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  "Scheme 对象不应保存在外部变量或数据结构中，                     │
│   因为内存管理系统可能会在 foreign procedure 调用之间            │
│   重定位或丢弃它们。"                                            │
│                                                                  │
│  解决方案:                                                       │
│  1. 使用 lock-object 锁定传递给 C 的代码对象                     │
│  2. 使用 foreign-callable-entry-point 获取稳定地址              │
│  3. 不再需要时调用 unlock-object                                │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
```

## 4. 线程模型与事件循环集成

### 4.1 原生线程支持

Chez Scheme 有完整的原生线程支持 (pthreads on Unix, Windows API on Windows)：

> "大多数原始 Scheme 过程是线程安全的，可以从多个线程并发调用。这包括分配操作如 cons 和 make-string..."

### 4.2 事件循环集成 — **最大挑战**

```
┌─────────────────────────────────────────────────────────────────┐
│                    事件循环集成问题                              │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  Neovim 架构:                                                    │
│  ┌─────────────────────────────────────────────────────────┐    │
│  │                     libuv 事件循环                       │    │
│  │  ┌─────────┐ ┌─────────┐ ┌─────────┐ ┌─────────────┐   │    │
│  │  │ stdin   │ │ timers  │ │ I/O     │ │ callbacks   │   │    │
│  │  └────┬────┘ └────┬────┘ └────┬────┘ └──────┬──────┘   │    │
│  │       │           │           │             │          │    │
│  │       └───────────┴───────────┴─────────────┘          │    │
│  │                           │                             │    │
│  │                           ▼                             │    │
│  │                    Lua 回调执行                         │    │
│  └─────────────────────────────────────────────────────────┘    │
│                                                                  │
│  Chez Scheme 问题:                                               │
│  - 阻塞 I/O 不与 libuv 集成                                     │
│  - 需要协程系统来 yield 到 libuv                                │
│  - 或者使用独立线程 + 显式同步                                  │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
```

### 4.3 解决方案

| 方案 | 复杂度 | 描述 |
|------|--------|------|
| **独立线程** | 中 | 在专用线程中运行 Scheme，显式同步 |
| **协程系统** | 高 | 实现 yield 到 libuv 的协程 (类似 Swish) |
| **异步库** | 中 | 使用 chez-a-sync 或 Swish |
| **Racket 模式** | 高 | 实现自己的协作式线程系统 |

来自 Swish 项目的经验：

> "在 Swish 中，我们实现了一种协程形式，使得特定协程可以阻塞等待异步 I/O 结果，同时其他协程继续运行。"

## 5. 内存管理与 GC 交互

### 5.1 分代垃圾收集器

Chez Scheme 使用**分代垃圾收集器**，与 Lua 的增量式 GC 不同。

### 5.2 与主机应用的内存集成

```c
// 可以提供自定义内存分配器
// 但 GC 仅在 Scheme 代码执行时运行
```

### 5.3 关键限制

| 特性 | Chez Scheme | Lua |
|------|-------------|-----|
| **GC 类型** | 分代 | 增量式 |
| **精确控制** | 有限 | 优秀 (`lua_gc`) |
| **C 持有对象** | 需要 `lock-object` | 可以持有引用 |
| **内存占用** | 5-10 MB | ~200 KB |
| **调试** | 困难 | 容易 |

### 5.4 GC 与 C 代码交互


## 8. 现有嵌入示例

### 8.1 Racket CS

Racket 使用 Chez Scheme 作为核心运行时：

> "Racket CS 使用 Racket 自己的线程系统，该系统在没有操作系统或 Chez Scheme 线程帮助的情况下实现，因此从 C 代码的角度来看，Racket 线程是协作式的。"

**启示**: 需要实现自己的线程/协程系统，而不是直接使用 Chez Scheme 的线程。

### 8.2 chez-exe

将 Chez Scheme 嵌入独立可执行文件的项目：

> "它通过将 boot 文件和 Scheme 程序嵌入 ELF 段，然后在运行时提取它们来工作。"

### 8.3 Swish

Erlang 风格的异步系统，基于 Chez Scheme：

> "Swish 实现了一种协程形式，使得特定协程可以阻塞等待异步 I/O 结果，同时其他协程继续运行。"

## 10. 推荐方案

### 10.1 不推荐: 直接替代

```
❌ 删除 Vimscript + Lua，用 Chez Scheme 替代

原因:
- 工作量巨大 (~20000 行核心代码)
- 生态归零 (95%+ 插件丢失)
- 无明显收益 (Neovim 不是计算密集型应用)
- 用户流失 (需要学习 Scheme)
```

### 10.2 推荐: 渐进式添加

```
✅ 添加 Chez Scheme 作为第三脚本语言

阶段 1: 研究与原型
├── 实现 C 桥接层
├── 实现基本的事件循环集成
└── 验证核心功能

阶段 2: 核心模块
├── 用 Scheme 实现一个核心模块 (如诊断)
├── 验证性能和可用性
└── 收集反馈

阶段 3: 评估
├── 评估用户体验
├── 评估性能影响
└── 决定是否继续
```

### 10.3 替代方案

| 方案 | 优点 | 缺点 |
|------|------|------|
| **保持 Lua** | 现状，生态丰富 | 无 Scheme |
| **添加 WASM** | 语言无关，安全，生态增长中 | 嵌入复杂 |
| **添加 Fennel** | Lisp 语法，编译到 Lua，兼容现有生态 | 不是真正的 Scheme |
| **添加 Janet** | Lisp 方言，嵌入友好 | 生态小 |
| **Guile Scheme** | GNU 项目，嵌入文档完善 | 比 Chez 大 |

### 10.4 如果坚持使用 Chez Scheme

```

│  └── 无明显收益 (Neovim 不是计算密集型应用)                      │
│                                                                  │
│  ─────────────────────────────────────────────────────────────  │
│                                                                  │
│  结论:                                                           │
│  技术上可行，但实际不推荐。                                      │
│  如果需要 Scheme 支持，建议作为第三语言渐进式添加，              │
│  而不是替代现有的 Lua 和 Vimscript。                            │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
```
